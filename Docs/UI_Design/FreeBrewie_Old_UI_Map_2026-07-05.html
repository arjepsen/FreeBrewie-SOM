Old Brewie UI Map

Reference document for the original Qt/QML Brewie UI found in reb20-develop/src/gui/ui. This maps the old screens, shared shell, navigation paths, overlays, and graphic vocabulary so the new LVGL UI can take inspiration without copying the old implementation.

This document is descriptive, not prescriptive. The old UI gives us product feel, screen names, assets, and user-flow clues. The new FreeBrewie UI should still use clean module boundaries, fast redraw behavior, and safer app-level action routing.

Screen or editor Fields and controls Interaction pattern Old sources
Create recipe Recipe name text field. Cancel returns back. Done creates the recipe when the name is non-empty, then opens the recipe menu. NewRecipe.qml
Rename / Save as recipe Single recipe-name text field. Opened from the recipe context menu. Save either renames or duplicates the active recipe depending on mode. Text input uses the shared keyboard overlay. RecipeMenu.qml, RecipeModify.qml, EditText.qml, Keyboard.qml
Details edit BJCP number selector, category selector, type selector, plus read-only style ranges for ABV, SRM, IBU, OG, and FG. Changing one BJCP selector updates the others and refreshes the style range fields. Save commits through the details view; Cancel/back discards. DetailsView.qml, DetailsForm.qml, InputSelector.qml
Ingredients tab screen Tabbed sections for fermentables and hops. Acts as a landing screen for ingredient sub-editors. The actual data entry happens in the fermentables and hops forms. IngredientsView.qml, TabbedPanel.qml
Fermentables form Bag panels. Each fermentable row has a fermentable selector, amount number field, and delete icon. Each bag has an Add Fermentables button. Selector opens the shared searchable ingredient selector. Amount opens numeric entry and is limited by remaining bag capacity. Save/Cancel are bottom actions. Fermentables.qml, FermentablesForm.qml, FermentablesItem.qml
Hops form Hop cage panels. Each hop row has hop selector, alpha-acid number field, amount number field, and delete icon. Each cage has Add Hop. Hop choice uses the shared selector. Amount is unit-converted between kg and grams/ounces. Save/Cancel are bottom actions. Hops.qml, HopsForm.qml
Brewing waters form Mash-in water temperature and amount. Optional sparging water temperature, time, amount, and delete sparge icon. Add Sparging reveals the sparging section. Numeric fields validate against recipe bounds and unit settings. Save/Cancel are bottom actions. Waters.qml, WatersForm.qml
Mashing steps form Scrollable mash step panels. Each step has temperature, time, and a delete icon except for the first step. Add More Step appends a mash step. Number fields validate temperature and time. Save/Cancel are bottom actions. Mashing.qml, MashingForm.qml
Hopping steps form Optional delayed hopping section with time. Hop cage sections show the hops in each cage and a cage time field. Add Delayed Hopping Step reveals the delayed-boil timer. Remove Delayed Hopping Step clears it. Each cage time is edited with numeric input. Hopping.qml, HoppingForm.qml
Cooling target editor Target cooling temperature, explanatory text, Modify button, then Save/Cancel while editing. Unlike most recipe editors, this behaves more like an inline edit panel inside the brewing tab section. Cooling.qml
Fermentation form Stage panels with Bottling and Racking toggles, duration, temperature, storage selector, ingredient rows, Add Ingredient, Delete Stage, and Add Stage. Fermentation ingredients have category selector, subtype selector, amount field, and delete icon. Subtype options depend on category: dry hop, fermentable, or yeast. Fermentation.qml, FermentationForm.qml, FermentationItem.qml
Shared selector popup Search/filter field, list rows, Cancel and OK buttons. Used by BJCP style selection, fermentable selection, hop selection, yeast and fermentation ingredient selection, time zone/language selection, and other pick lists. InputSelector.qml, Selector.qml
Shared number/text entry Numeric editor with header/subheader/range validation, and text editor with keyboard overlay. Used broadly by recipe forms. Old UI relies heavily on dynamic text and modal input overlays; our LVGL design should preserve clarity but keep updates lean. EditNumber.qml, InputNumpad.qml, EditText.qml, Keyboard.qml

What To Carry Forward

Good inspiration

  • Warm orange on charcoal/black.
  • Large touch rows for menu, extras, and settings.
  • Clear recipe browsing -> recipe detail -> brew flow.
  • Home as the normal landing screen.
  • Status/progress split during active brewing.
  • Graphic machine/tank vocabulary for service and process screens.

Things not to copy blindly

  • Heavy full-screen slide transitions on the A13 SOM.
  • UI directly invoking machine actions without our new safety routing.
  • Hidden debug access via recipe search magic strings.
  • Dense edit screens before we know which workflows are needed first.
  • String-heavy dynamic UI updates where raw values and dirty widgets are better.
